### Integration fixtures (`tests/integration/conftest.py`)

- **`database_url`** (session scope): drops and recreates `spm_test`, then runs `upgrade head`.
- **`engine`** (per test): a `NullPool` engine.
- **`session_factory`** (per test): every table is `TRUNCATE`d afterwards. I chose truncation over transaction
  rollback because the advisory-lock test needs two real concurrent transactions.
- **`redis_client`**: Redis DB 15, flushed before and after each test.
- Override the targets with `SPM_TEST_DATABASE_URL` and `SPM_TEST_REDIS_URL`.

### `spm_ensure_report_partitions(months_ahead int) RETURNS int`

For each month from the current UTC month through `+months_ahead`, if `reports_yYYYYmMM` is missing it:

1. creates the table with `LIKE reports`,
2. **moves any rows for that month out of `reports_default`** into it,
3. `ATTACH`es it with bounds `[month start, next month start)` in UTC.

Step 2 matters because Postgres refuses to attach a partition while the default partition holds rows for that range.

The function also:
- returns how many partitions it created,
- rejects negative input,
- takes a transaction-scoped advisory lock, so the migration and the nightly M17 job can't race.

## Deviations (also in the Decision log)

- **Partition function behaviour** is as described above: the default partition is named `reports_default`, rows
  are moved out of it before attaching, an advisory lock is taken, and the function returns a count.
- **The migration splits its DDL into single statements,** because asyncpg can't run multi-statement strings. The
  downgrade keeps `postgis`.
- **The `tables.py` vs DB diff is enforced by a test.**
- **The container now owns the engine,** and `/readyz` uses it.
- **Test databases are cloned from `template_postgis`.** This cut the integration run from about 26 s to about 14 s.
- **ruff skips line length (`E501`) for `migrations/versions/*`,** so the DDL stays identical to MODULES.md.

## Known limitations

- **`PgUnitOfWork` doesn't type-check as `UnitOfWork` yet.** Its repository attributes are added as each repository
  is built (M04 onward).
- **Report partitions only exist through +12 months.** Without the nightly M17 job, rows after that land in
  `reports_default`. When the function later creates those months it moves the rows out, so the cost is slower
  queries, not lost data.
- **The `session_factory` fixture truncates every table,** so integration tests can't run in parallel against one DB.
