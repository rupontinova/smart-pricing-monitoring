### Seed validation

`build_catalog` rejects, with a `SeedError` naming the problem:
- duplicate area, product or shop ids
- shops in unknown areas
- invalid IANA timezones
- `abs_min ≥ abs_max`
- unknown base units, or `half_life_h ≤ 0`
- unknown keys
- aliases that collide with another product's alias, id or name after normalization
- aliases that are empty after normalization

### Seeding

- **One transaction:** areas, products, aliases and shops are upserted together; then `spm:geo:shops` is rebuilt from
  the database.
- **Half-life is protected:** `half_life_h` is only overwritten while it still equals `default_half_life_h`. Once M17
  tunes it, the tuned value is kept, though the default still updates.
- **Display order:** `sort_order` is the product's position in the YAML.
- **Upsert only, never delete.** To retire a product or shop, set `active: false`.

### CatalogCache

- `ensure_fresh()` reloads when the snapshot is ≥ 300 s old. A lock stops concurrent callers from loading twice.
- If a refresh fails while an old snapshot exists, the old one keeps being served and the next call retries. With no
  snapshot at all, the error propagates.
- Sync getters: `product`, `products`, `alias_map`, `area`, `areas`, `shop`, `shops`, `shops_in_area` (active shops).

### API

- `GET /v1/products`: active products in display order, each with `aliases[]` (normalized) and `unit_presets[]`
  (numbers, e.g. `{"q": 250, "u": "g"}`).
- `GET /v1/areas`: `[{id, name, timezone, center: {lat, lng}}]`.
- `GET /v1/shops?area=&lat=&lng=&radius_m=`: active shops `{id, name, area_id, location, address, distance_m}`.
  - With `lat`/`lng`: only shops within `radius_m` (default 2000, maximum 50 000), nearest first, `distance_m`
    rounded to 0.1 m.
  - Otherwise: sorted by name, with `distance_m: null`.
  - Giving only one of `lat`/`lng`, or a radius out of range, gives a 422 `VALIDATION_ERROR`.
  - An unknown `area` gives a 404 `NOT_FOUND`.
  - With no DB configured the endpoints return a 503 `SERVICE_UNAVAILABLE`; with no Redis, so does a nearby search.

## How to run

```bash
make up && make migrate seed       # gmake on this Mac
make api
curl localhost:8000/v1/products
curl "localhost:8000/v1/shops?lat=23.7808&lng=90.4073&radius_m=1000"
```

## Deviations (also in the Decision log)

- **`normalize_text` arrived early,** in M04, and keeps combining marks.
- **New `ShopGeoIndex` port:** `HotCache` extends it.
- **`CatalogCache`** has an async `ensure_fresh()`, sync getters, and serves the old snapshot when a refresh fails.
- **`spm:geo:shops` is also rebuilt at API startup.**
- **Seeding never deletes.**
- **`/v1/shops` and `/v1/products`** follow the rules in the API section above.
- **`create_app(container=…)`** accepts a pre-built container.

## Known limitations

- Prices, coordinates and the timezone are placeholders.
- Aliases removed from the YAML stay in the database. Delete them by hand if one becomes wrong.
- Each API process has its own `CatalogCache`, so a catalog change can take up to 300 s to show up.
