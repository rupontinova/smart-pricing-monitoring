# M05 — Normalizer (B)

**Status:** ✅ done 2026-10-22, on branch `develop`.

## What was built

### `spm/core/units.py`

- **`UNIT_SYNONYMS`:** exactly the plan's spellings → `g, kg, ml, l, piece, hali, dozen, tray`.
- **`UNITS`:** each unit's dimension and factor to its base unit. Fractions use `Decimal` at 10 significant digits:

  | Unit | Factor |
  |---|---|
  | piece | 0.08333333333 |
  | hali | 0.3333333333 |
  | tray | 2.5 |

- **`BASE_DIMENSION`:** kg → MASS, l → VOLUME, dozen → COUNT.
- **`parse_unit(text)`:** lowercases, strips, and drops a trailing `.`. Unknown text raises `UnknownUnit` with
  `known_units`.
- **`units_for(dimension)`:** the units of a dimension, smallest first (used in error extras).

### `spm/core/normalizer.py`

- **`ProductCatalog` protocol:** sync `product(id)`, `products()` and `alias_map()`. `CatalogCache` satisfies it,
  which the tests check with mypy.
- **`normalize_text(s)`:** from M04.
- **`levenshtein(a, b)`** and **`similarity(a, b)`:** `100 × (1 − d / (len a + len b))`; see Deviations.
- **`resolve_product(product_id, product_text, catalog)`** tries, in order:
  1. the `product_id`, if given. Missing or inactive → `UnknownProduct` with suggestions.
  2. the normalized text as an exact alias, then as an exact product id or name.
  3. a fuzzy match. It resolves only if:
     - the text is at least `FUZZY_MIN_LENGTH` (5) characters,
     - the best score is ≥ `FUZZY_MATCH_MIN_SCORE` (85),
     - exactly one product has that best score.
  4. otherwise `UnknownProduct(query, suggestions=[up to 3 ids scoring ≥ 60])`.

  Inactive products never resolve. Empty text gives a `VALIDATION_ERROR`.
- **`normalize(raw, catalog) -> NormalizedPrice`:**
  1. `price` must be > 0, finite and have ≤ 2 dp; `quantity` must be > 0 and finite. Otherwise a `VALIDATION_ERROR`
     with `fields`.
  2. Resolve the product, then parse the unit. If the dimension is wrong for the product, raise `UnitMismatch` with
     `unit, product_id, base_unit, allowed_units`.
  3. `base_quantity = quantity × factor` must be in [0.05, 50] (inclusive). Otherwise raise `QuantityOutOfRange` with
     `base_quantity, min, max, base_unit`.
  4. `norm_price = price / base_quantity`, quantized to 0.0001 with `ROUND_HALF_EVEN`.

### `spm/constants.py`

| Constant | Value |
|---|---|
| `BASE_QUANTITY_MIN` | `Decimal("0.05")` |
| `BASE_QUANTITY_MAX` | `Decimal("50")` |
| `FUZZY_MATCH_MIN_SCORE` | 85 |
| `FUZZY_MIN_LENGTH` | 5 |
| `FUZZY_SUGGEST_MIN_SCORE` | 60 |
| `FUZZY_MAX_SUGGESTIONS` | 3 |

The normalizer is pure: standard library plus `spm.core` and `spm.constants`. Both import-linter contracts are kept.

## Deviations (also in the Decision log)

1. **The similarity formula is `1 − d / (len a + len b)`.** The plan requires "oniun" → onion at threshold 85. With
   the max-length ratio, or python-Levenshtein's `ratio`, one typo in a 5-letter word scores 80, so the plan's own
   test couldn't pass.

   | Pair | max-length | sum-length (used) |
   |---|---|---|
   | oniun / onion | 80.0 | 90.0 |
   | tomatto / tomato | 85.7 | 92.3 |
   | chai / chal | 75.0 | 87.5 |
   | xyz / oil | 0.0 | 50.0 |

2. **`FUZZY_MIN_LENGTH = 5`.** Without it, "chai" (tea) silently became rice through the alias "chal". Short text now
   only gets suggestions.
3. **Validation failures in step 1 use `VALIDATION_ERROR`,** as listed in Verification above.
4. **`base_quantity` isn't rounded;** M08 rounds it to the column's 4 dp when storing.

## Known limitations

- **Sum-length scores never drop below about 50,** because the distance can't exceed the longer word's length. So
  `FUZZY_SUGGEST_MIN_SCORE = 60` is fairly permissive: "xyz" gets a suggestion.
- **Fuzzy matching compares the whole text against each name.** Extra words, like "fresh onion from market", won't
  match. That would need token-level matching, which isn't planned.
- **No unit-error hints yet.** "Did you mean 500 g?" arrives in M06.
