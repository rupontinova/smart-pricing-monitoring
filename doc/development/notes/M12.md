# M12 — Fair-price band & hot cache (F, G)

**Status:** ✅ done 2026-10-22, on branch `develop`.

## What was built

### `spm/core/band.py` (pure)

- **Label sets:** `BAND_INCLUDED` = NORMAL, MARKET_SHIFT; `SHOP_INCLUDED` adds SHOP_OUTLIER.
- **`band_window_start(now, half_life_h, rebase_at)`:** `now − min(4 × half-life, 60 d)`, or `rebase_at` if that's
  later.
- **`compute_band(...) -> FairBand`:**
  1. Keep observations with an included label inside the window.
  2. Weight each one with `report_weight`, then cap any shop at 40% with `cap_group_share`.
  3. The weighted p25/p50/p75 and the MAD around p50.
  4. `total_weight` (uncapped), `n_eff` (capped), and `n_shops` (shops with weight).
  5. Confidence: HIGH (≥ 3.0 and ≥ 3 shops), MEDIUM (≥ 1.5), LOW (≥ 0.5), otherwise STALE. With no observations it's
     STALE with `None` quantiles; with zero total weight the quantiles are computed unweighted.
  6. `newest_obs_at` and the weight-averaged `mean_age_h`.
- **`compute_shop_prices(...)`:**
  - Per shop, it keeps the included labels and drops the shop if its newest report has freshness below 0.25.
  - It then calls `verified_shop_price`. If the price isn't verified, the newest price is shown with
    `verified=False`.
  - It also fills `support_weight`, `n_reports`, `last_observed_at` and `verified_at`.
- **`cache_ttl_s(half_life_h)`:** `max(2 × half-life, 24 h)` in seconds.

### Hot cache

- **`adapters/redis/hot_cache.py` (`RedisHotCache`, completed):**
  - `put_band` (MULTI: DEL, HSET, EXPIRE) and `get_band` (HGETALL).
  - `put_shop_prices` (MULTI: DEL both keys, ZADD, HSET JSON, EXPIRE both).
  - `cheapest`: `ZRANGEBYSCORE -inf (max LIMIT 0 limit×3`, hydrated with HMGET, verified prices only, cut to
    `limit`.
  - `shop_price` (HGET), plus M04's geo methods.
- **`adapters/cache_codec.py`:** band hash encoding (ISO timestamps, `""` for None) and shop-price JSON, shared by
  the Redis adapter.
- **`adapters/memory/hot_cache.py` (`MemoryHotCache`):** the same behaviour in memory. With a clock, TTLs expire.
  `flush()` empties it, and `ttls` records the last TTL used.

### Repositories

- **`PgBandRepo`, complete:**
  - `get_band` and `upsert_band`: prices go through `Decimal`, rounded half-even to 4 dp.
  - `get_rebase` and `set_rebase`: creates the `band_state` row from the product's half-life if it's missing.
  - `upsert_shop_price`.
  - **`replace_shop_prices`:** DELETE plus one multi-row INSERT.
  - `shop_prices`.
- **`PgAssessmentRepo`:**
  - `observations_for_area(product, area, since, exclude_shop=None)`, using `ra_area_idx`.
  - `observations_for_shop`.
  - Both join `reporters` for the current trust (α/(α+β)) and return every label (callers filter), newest first.
- **`PgReporterRepo.high_trust_ids(ids)`:** the high-trust rule in SQL.
- **Memory versions** of all of the above.

### `services/band_service.py` (`BandService(hot_cache, uow_factory, clock)`)

- **`recompute(uow, product, area_id, now)`:**
  - **One query:** loads every observation since `min(band window start, now − 2 half-lives)`, so it covers both the
    band and the shop prices. A re-base narrows the band but not the shop prices.
  - **Computes:** the band and the shop prices, using the high-trust ids.
  - **Saves:** `upsert_band` and `replace_shop_prices`. The caller commits.
- **`publish_to_cache(band, prices)`:** call it after commit. The TTL comes from `cache_ttl_s`.
- **`get_or_rebuild(area_id, product_id)`:** a cache hit returns the band. On a miss it reloads `band_state` and
  `shop_prices` from Postgres, drops prices that have gone stale since, re-publishes, and returns the band, or None
  if there's no band.

## Bugs found while building this

- **M09's `cap_group_share` crashed when every weight was 0.** The infeasible-cap branch took `min()` of an empty
  set. It now returns the weights unchanged; a regression test is in `test_stats.py`.
- **`replace_shop_prices` failed on Postgres:** executemany can't carry `now()` as a parameter. It now uses a
  multi-row `VALUES` insert. Only the integration test could catch this, because the memory adapter has no SQL.
- **My half-even test expected 80.1235 for 80.12345.** That's a tie, and half-even correctly gives 80.1234.

## Deviations (also in the Decision log)

- **`FairBand` quantiles are optional.**
- **New repo methods:** `replace_shop_prices` and `high_trust_ids`.
- **Shop-price field definitions:** `support_weight`, `verified_at` and the unverified `n_reports` were undefined in
  the plan (see `compute_shop_prices` above).
- **Zero-weight handling** in the band and the cap.
- **The cache JSON carries `support_weight`;** writes replace the whole key.
- **`get_or_rebuild` returns the band,** and re-filters stale shop prices before caching.
- **New `CACHE_TTL_MIN_H` constant** and container `hot_cache` field.

## Known limitations

- **The shop cap fights freshness when few shops have data.** With fewer than 3 contributing shops, the 40% cap
  can't be met, so `cap_group_share` gives them equal weight (M09's rule). A stale shop can then weigh as much as a
  fresh one: one fresh shop at 80 and one 3-half-life-old shop at 60 give p50 = 70. The plan's own one-pass rule
  would be worse (60). Confidence stays honest, because it uses the uncapped total. If this matters in practice, change
  `cap_group_share` to skip capping when the cap is infeasible, rather than equalizing.
- **Nothing triggers a recompute yet.** M13 does, after scoring, and M17 nightly.
- **`cheapest` only looks at `limit × 3` candidates.** If many cheaper shops are unverified it can return fewer than
  `limit`, as the plan specifies.
