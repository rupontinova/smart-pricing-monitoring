# M09 — Robust statistics library

**Status:** ✅ done 2026-10-22, on branch `develop`.

## What was built

`spm/core/stats.py`: pure, typed functions on plain floats (strict mypy).

| Function | Notes |
|---|---|
| `weighted_quantile(values, weights, q)` | Midpoint plotting positions `c_i = (S_i − w_i/2) / S`, clamped at the ends, linear interpolation in between. Zero weights are dropped. Raises `ValueError` on empty input, zero total weight, mismatched lengths, q outside [0, 1], or negative or non-finite weights. Ties sort by `(value, weight)`, so the result doesn't depend on input order. |
| `weighted_median`, `median` | `q = 0.5`; `median` uses all weights = 1 |
| `mad`, `weighted_mad` | Median (weighted median) of `|x − center|`; the center defaults to the (weighted) median |
| `robust_z(x, center, mad)` | `(x − center) / (1.4826 × max(mad, 0.02 × |center|))`; 0.0 if the denominator is 0 |
| `freshness_weight(age_h, half_life_h)` | `0.5 ** (max(age, 0) / half_life)`; `half_life ≤ 0` raises |
| `effective_n(weights)` | `(Σw)² / Σw²`; 0 when there's no weight |
| `cap_group_share(weights, groups, max_share)` | Water-filling cap per group; see Deviations |
| `log_ratio(a, b)` | `ln(a / b)`; non-positive values raise |
| `daily_log_returns(series)` | Consecutive log returns over the positive, finite values |
| `half_life_from_volatility(daily_medians)` | `σ = 1.4826 × MAD(returns)`. None with fewer than 10 returns or σ = 0; otherwise `round(clamp(0.10 / σ × 24, 24, 504))` hours |

### Shift-equivariance test fix

Hypothesis found `values = [0.0, 1.0, -9e-218]`, `c = 1.0`. In floating point `-9e-218 + 1.0 == 0.0 + 1.0`, so two
distinct points became a tie and the quantile legitimately changed. The midpoint-position definition depends on how
many distinct points there are, so this is a float artifact, not a bug. The property now uses values that shift
exactly: multiples of 1/4 with integer shifts.

## Deviations (also in the Decision log)

- **`cap_group_share` uses water-filling** rather than the plan's single pass. For one dominant shop the result is
  identical (80% → 40%). With several groups over the cap, a single pass against the original totals leaves them all
  above it (45/45/10 at 40% → about 44% each); water-filling caps all of them at exactly 40%. If capping is
  impossible (fewer than `1/max_share` groups carry weight) the capped groups are equalized. A single group is left
  as is, because the plan's formula would have set its weight to 0.
- **`HALF_LIFE_MIN_RETURNS` is now a constant.**
- **Stricter input validation** across the functions, as listed in the table above.

## Known limitations

- **The quantile can jump** when two distinct values merge into one: the midpoint-position definition gives each
  distinct point its own position. This is inherent to the plan's definition and has no practical effect on prices
  with 4 decimal places.
- **Statistics run on `float`;** callers convert to and from `Decimal` at the boundaries (§2.4).
